## Контрольные вопросы

1. **В чём разница между юнит-тестом и интеграционным?**
   - Юнит-тест проверяет один компонент изолированно (с моками), интеграционный – взаимодействие нескольких компонентов (например, код + реальная БД).

2. **Почему юнит-тестов должно быть больше, чем E2E?**
   - Юнит-тесты быстрые, дёшевые, легко поддерживать. E2E-тесты медленные, хрупкие, их сложно отлаживать. По пирамиде тестирования: много юнитов, меньше интеграционных, ещё меньше E2E.

3. **Зачем использовать testcontainers вместо in-memory БД?**
   - In-memory БД (SQLite) может вести себя иначе, чем реальная PostgreSQL (типы данных, ограничения, транзакции). Testcontainers поднимает настоящий контейнер с PostgreSQL, гарантируя одинаковое поведение в тестах и проде.

4. **Что тестирует Mutation Testing?**
   - Мутационное тестирование изменяет код (вносит "мутации": меняет > на >=, удаляет вызовы) и проверяет, что тесты падают. Если тест не упал – мутация выжила, значит тест слабый.
